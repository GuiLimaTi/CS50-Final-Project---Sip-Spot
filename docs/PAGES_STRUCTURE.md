# Pages Structure - Sip Spot

## Project Title
Sip Spot

## Purpose of This Document
This document defines the main pages of the Sip Spot web application and explains the purpose of each page.

Its goal is to organise the user flow clearly and describe how each page contributes to the overall experience of the application.

For Version 1, Sip Spot follows a simple and practical structure focused on helping users search, compare, and review coffee shops in the Temple Bar area of Dublin.

---

## General User Flow
The main flow of the application is:

**Home Page → Results Section on the Home Page → Coffee Shop Details Page**

There is also a supporting page:

**Home Page → About Page**

This creates a simple and effective user journey.

The user enters the home page, applies filters, reviews matching coffee shops, and can then open a details page for one selected café. If needed, the user can also visit the About page to understand the purpose of the project.

---

## 1. Home Page

### Purpose
The Home Page is the main entry point of the application.

It introduces Sip Spot, establishes the project branding, and allows the user to begin searching immediately.

This is the most important page for first impressions and should make the purpose of the application clear at a glance.

### Main Elements
The Home Page includes:

- application branding and logo
- navigation menu
- hero section
- search and filter form
- button to search for matching coffee shops
- results section showing matching coffee shop cards

### Main User Actions
On this page, the user can:

- choose a coffee type
- choose a maximum price
- select work-friendly preference
- select sit-in / takeaway preference
- select Irish coffee preference
- select opening time preference
- select closing time preference
- submit filters to search for matching coffee shops
- review the filtered results directly on the page
- open a specific coffee shop details page

### Notes
In Version 1, the search experience is integrated into the Home Page rather than separated into a completely different results page.

This makes the experience more direct and keeps the application simple for the user.

---

## 2. Results Section on the Home Page

### Purpose
The Results Section displays the coffee shops that match the selected filters.

In the current Version 1 structure, the results are shown directly below the filter area on the Home Page. This performs the same role as a traditional search results page while keeping the application more streamlined.

### Main Elements
The Results Section includes:

- a section title
- a short results summary
- a list of matching coffee shop cards

### Information Displayed in Each Card
Each coffee shop card may show:

- coffee shop image
- coffee shop name
- short address
- selected coffee type and price
- rating
- sit-in / takeaway availability
- work-friendly label
- Irish coffee availability
- opening time
- closing time
- short notes
- button or link to view more details

### Main User Actions
In this section, the user can:

- review matching coffee shops
- compare basic information quickly
- decide which place seems most suitable
- click to open the details page of a specific coffee shop

### Notes
Although this is not a separate page, it still acts as the main comparison area of the application.

Its role is to help users scan options quickly and move to a more detailed view only when needed.

---

## 3. Coffee Shop Details Page

### Purpose
The Coffee Shop Details Page shows the complete information for one selected coffee shop.

This page is more detailed than the results cards and helps the user make a final decision.

### Main Elements
The Details Page includes:

- coffee shop image
- coffee shop name
- full address
- rating
- coffee types available
- price list by coffee type
- work-friendly category
- sit-in / takeaway information
- Irish coffee availability
- opening time
- closing time
- notes or short description
- button to go back to results

### Main User Actions
On this page, the user can:

- read full information about the selected coffee shop
- review all available coffee types and prices
- check practical details before visiting the place
- return to the previous search experience

### Notes
This page is designed to be more informative and less comparative than the results section.

It supports the final part of the decision-making process.

---

## 4. About Page

### Purpose
The About Page explains the idea behind Sip Spot and the problem the project is trying to solve.

It adds context to the application and helps users understand why the project exists and why the focus is on Temple Bar.

### Main Elements
The About Page includes:

- short project description
- explanation of the problem the app solves
- why Temple Bar was chosen
- explanation of the practical filter categories
- technologies used in the project

### Main User Actions
On this page, the user can:

- read about the purpose of the application
- understand the design choices behind the project
- understand the project’s local focus

### Notes
This page is not the main functional part of the application, but it improves the professionalism of the site and helps the project feel more complete.

---

## Recommended Version 1 Pages
The main page structure for Version 1 is:

1. Home Page
2. Coffee Shop Details Page
3. About Page

The Home Page also includes the results display section, which performs the role of a traditional search results page.

This structure is enough to create a complete, functional, and realistic user experience for the first version of Sip Spot.

---

## Future Page Possibilities
If the project expands in the future, it may include additional pages such as:

- favourites page
- map page
- login page
- user account page
- ranking page
- review submission page
- admin or data entry page

These pages are not part of Version 1.

---

## Final Structure Summary
For Version 1, Sip Spot uses a simple structure built around a Home Page with integrated filtering and results, a Coffee Shop Details Page for full information, and an About Page for project context.

This structure keeps the application focused, manageable, and strong enough for the CS50 final project while still allowing room for future expansion.
